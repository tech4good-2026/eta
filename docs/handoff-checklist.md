# 개발·시연 인계 체크리스트

## 1. 역할과 기준 문서

| 담당 | 책임 | 기준 |
|---|---|---|
| 기획·리서치 | 기능 우선순위, 사용자 문구, 데이터 출처·한계 | `functional-spec.md` |
| 디자인 | 모바일 화면, 바텀시트, 로딩·오류·접근성 상태 | 기능 ID와 Mock 시나리오 |
| 프론트엔드 | React/Vite 화면, 카카오맵, Mock/실제 API 교체 | `openapi.yaml`, `mocks/` |
| 백엔드 | 인증, 프로필, 공급자 어댑터, 캐시, 안내 세션 | `api-spec.md`, `openapi.yaml` |
| 경로 엔진 | 접근성 판정, 개인화 ETA, 경로 정렬 | `route-engine-contract.md` |

OpenAPI가 필드와 Enum의 최종 기준입니다. 계약 변경은 OpenAPI → Mock → 프론트 타입 → 백엔드 모델 순서로 동시에 반영합니다.

## 2. 개발 시작 전

- [ ] 기능 ID별 담당자와 완료 시점을 지정했습니다.
- [ ] 프론트가 모든 Mock 화면을 단독으로 실행할 수 있습니다.
- [ ] 백엔드와 경로 엔진 담당자가 입력·출력 모델을 함께 확인했습니다.
- [ ] 시연 경로의 출발·도착 좌표와 시나리오를 고정했습니다.
- [ ] 실제 데이터와 합성 Mock을 화면·발표에서 구분하는 문구를 정했습니다.
- [ ] 외부 API 한도와 장애 시 행동을 정했습니다.

## 3. 환경변수와 키

### 프론트

```env
VITE_API_BASE_URL=http://localhost:8000/api/v1
VITE_KAKAO_MAP_KEY=...
```

### 백엔드

```env
ROUTE_PROVIDER=mock
DEMO_TOKEN=demo-token
CORS_ORIGINS=["http://localhost:5173"]
TMAP_APP_KEY=...
SEOUL_API_KEY=...
SEOUL_SUBWAY_API_KEY=...
SEOUL_BUS_API_KEY=... # 공공데이터포털 디코딩 인증키
```

- [ ] 실제 키가 Git에 포함되지 않았습니다.
- [ ] 카카오 웹 도메인에 localhost와 배포 도메인을 등록했습니다.
- [ ] TMAP 호출은 백엔드에서만 이루어집니다.
- [ ] FastAPI CORS는 `CORS_ORIGINS`에 등록한 프론트 주소만 허용합니다.
- [ ] `ROUTE_PROVIDER=tmap`에서는 TMAP·서울 일반·서울 실시간 지하철 키가 모두 등록되어 있습니다.
- [ ] 실시간 저상버스를 시연한다면 공공데이터포털의 노선정보조회·버스도착정보조회 활용 신청 후 `SEOUL_BUS_API_KEY`를 등록했습니다.

## 4. 데이터 출처와 화면 표시

| 데이터 | 공급자 | 화면 상태 | 장애 시 |
|---|---|---|---|
| 지도 | Kakao Maps JavaScript SDK | 지도 저작권 표시 유지 | 검색·리스트 UI 유지 |
| 장소 | Kakao Local API | 공급자 장소명·주소 | 재시도 또는 직접 좌표 불가 안내 |
| 대중교통 경로 | TMAP Transit | `SCHEDULED` | 후보 경로 10분 캐시 또는 오류 |
| 버스 도착·저상 여부 | 서울 버스 API | `REALTIME`, `SEOUL_OPEN_DATA` | `UNKNOWN` 경고 후 시간표 유지 |
| 지하철 도착 | 서울 실시간 지하철 API | `REALTIME`, `SEOUL_OPEN_DATA` | 시간표 출발시각 유지 |
| 택시·도보 | TMAP 자동차·보행 경로 | `ESTIMATED` | 해당 탭 오류, 다른 탭 유지 |
| 경사·단차 | 현재 합성 fixture, 후속 팀원 모듈 | `SYNTHETIC_FIXTURE` | `UNKNOWN` 경고 |
| 지하철 시설 | 서울교통공사 공공데이터 | 상태·갱신시각 | `UNKNOWN` 경고 |
| 경사·보행 접근성 | 서울 데이터와 팀 가공값 | `VERIFIED/ESTIMATED/UNKNOWN` | 안전 보장 금지, 주의 경고 |

- [ ] 모든 데이터에 `generatedAt` 또는 `observedAt`을 보존합니다.
- [ ] `UNKNOWN`을 `AVAILABLE`이나 `false`로 변환하지 않습니다.
- [ ] TMAP 데이터는 24시간 이상 저장하지 않으며 MVP 캐시는 10분입니다.

## 5. 대표 시연 시나리오

### A. 대중교통 개인화

1. 수동 휠체어, 엘리베이터·저상버스 필수 프로필로 로그인합니다.
2. 서울역에서 잠실역을 검색합니다.
3. 일반 ETA와 개인화 ETA의 차이, 엘리베이터 상태, 접근 가능한 경로 우선 정렬을 설명합니다.

### B. 저상버스 불확실성

1. 강남역에서 서울성모병원을 검색합니다.
2. 저상버스 확인 경로와 확인되지 않은 경로의 배지·경고 차이를 보여줍니다.
3. 필수 조건을 만족하지 못하면 택시 대안을 보여줍니다.

### C. 지하철 놓침 재탐색

1. 서울역에서 잠실역 안내를 시작합니다.
2. 시청역에서 `지하철을 놓쳤어요`를 선택합니다.
3. 시청역이 새 출발점이 되고 `routeRevision`이 1에서 2로, ETA가 갱신되는 것을 보여줍니다.

### D. 도보·택시 비교

1. 서울역에서 서울시청을 검색합니다.
2. 개인화 도보시간·경사 경고와 택시 예상시간·예상요금을 비교합니다.

## 6. 장애 대비

- [ ] 각 대표 시나리오의 합성 fixture를 발표 기기에 포함했습니다.
- [ ] 실제 API 실패 시 자동으로 성공한 것처럼 가장하지 않고 `시연 데이터`임을 표시합니다.
- [ ] TMAP 종량제 또는 호출 한도를 설정하고 예상 호출량을 확인했습니다.
- [ ] 발표 직전 실제 검색을 수행하고 `generatedAt`, 시설 상태와 경로를 확인했습니다.
- [ ] 배포 URL, 로컬 실행, 화면 녹화 중 두 가지 이상의 시연 수단을 준비했습니다.

## 7. 개인정보와 접근성

- [ ] 위치 권한 요청 전에 이용 목적을 설명합니다.
- [ ] 원본 좌표가 DB·로그·분석도구에 기록되지 않는지 확인합니다.
- [ ] 이메일·프로필을 TMAP·Kakao 요청에 포함하지 않습니다.
- [ ] 탈퇴 시 계정·프로필·속도 집계가 삭제됩니다.
- [ ] 버튼 터치 영역, 키보드 포커스, 스크린리더 레이블과 색상 외 상태 표현을 확인합니다.

## 8. 완료 정의

- [ ] 모든 Mock JSON이 OpenAPI 스키마를 통과합니다.
- [ ] 정상·빈 결과·주의·오류 상태가 프론트에서 각각 표현됩니다.
- [ ] 백엔드 응답이 Mock과 같은 Pydantic/OpenAPI 모델을 사용합니다.
- [ ] 경로 엔진 테스트 벡터가 통과합니다.
- [ ] 같은 안내 세션에서 재탐색 후 `routeRevision`이 증가합니다.
- [ ] 안내 종료 후 원본 위치가 저장되지 않고 속도 집계만 남습니다.
- [ ] 실제·시간표·추정·미확인·Mock 데이터가 명확하게 구분됩니다.
- [ ] 백엔드 `uv run pytest`, `uv run ruff check .`, Docker health 검증이 통과합니다.
