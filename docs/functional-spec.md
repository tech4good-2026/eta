# 교통약자 맞춤 이동 내비게이션 기능 명세서

- 문서 버전: 1.0.0
- 기준일: 2026-07-15
- 대상: 기획, 디자인, React 프론트엔드, FastAPI 백엔드, 개인화 경로 엔진 담당자

## 1. 목표와 성공 기준

사용자가 자신의 이동 조건을 등록하고 목적지를 검색하면, 서비스는 일반 경로의 시간표와 보행시간을 사용자 속도·보조기구·필수 접근성 조건으로 보정합니다. 안내 도중 대중교통을 놓치거나 경로에서 이탈하면 현재 위치 또는 사용자가 지정한 현재 역을 새 출발점으로 사용해 경로와 ETA를 갱신합니다.

MVP 성공 기준은 다음과 같습니다.

1. 가입부터 프로필 등록, 목적지 검색, 세 가지 이동수단의 경로 비교, 상세 경로, 안내 시작까지 한 흐름으로 동작합니다.
2. 경로 카드에 일반 ETA와 개인화 ETA가 함께 표시됩니다.
3. 접근 가능한 경로가 우선 노출되며, 확인할 수 없는 정보는 명시적으로 `UNKNOWN` 상태로 표시됩니다.
4. `지하철을 놓쳤어요`를 선택하면 같은 안내 세션에서 출발점, 경로, ETA와 `routeRevision`이 갱신됩니다.
5. 안내 중 수집한 원본 좌표는 저장하지 않고 유효한 보행속도 집계만 계정에 반영합니다.

## 2. 범위

### 포함

- 이메일·비밀번호 기반 회원가입, 로그인, 로그아웃, 회원 탈퇴
- 최초 이동 프로필 등록과 이후 수정
- 현재 위치 또는 검색 장소를 출발지·도착지로 지정
- 대중교통, 택시, 도보 경로 탐색
- 저상버스, 계단, 엘리베이터, 급경사 등 접근성 상태 표시
- 지도 경로와 바텀시트 상세정보
- 전경 상태의 위치 기반 안내, 이탈 감지, 사용자 확인형 재탐색
- 안내 종료 후 평균 보행속도 자동학습
- 서울시 범위의 데이터 품질 보장

### 제외

- 실제 택시 호출, 예약, 결제
- 화면을 닫은 상태의 백그라운드 위치추적
- 지하철·버스 승차 여부의 완전 자동 판정
- 카메라 기반 장애물 인식
- 이메일 인증, 비밀번호 재설정, 소셜 로그인, 리프레시 토큰
- 서울 외 지역의 동일한 접근성 데이터 품질 보장

## 3. 사용자 프로필

### 사용자 유형 `TravelerType`

- `PREGNANT`: 임산부
- `SENIOR`: 고령자
- `MOBILITY_IMPAIRED`: 지체·이동 제약 사용자
- `TEMPORARILY_INJURED`: 일시적 부상자
- `CAREGIVER_WITH_CHILD`: 영유아 동반자
- `OTHER`: 기타

### 보조기구 `MobilityAid`

- `MANUAL_WHEELCHAIR`, `POWER_WHEELCHAIR`, `STROLLER`
- `CANE`, `CRUTCHES`, `WALKER`

유형과 보조기구는 각각 복수 선택할 수 있습니다. 보조기구를 사용하지 않으면 빈 배열을 전송합니다.

### 접근성 선호

- `avoidStairs`: 계단이 포함된 경로 회피
- `elevatorRequired`: 지하철 이용 시 엘리베이터 필수
- `lowFloorBusRequired`: 버스 이용 시 저상버스 필수
- `avoidSteepSlopes`: 급경사 구간 회피

### 보행속도

- 최초 값은 개인화 엔진이 프로필을 기준으로 계산하며, 대응값이 없으면 MVP 공통 기본값 `1.0m/s`를 사용합니다.
- 정확도·시간 간격·속도 범위를 만족하고 이전·현재 좌표가 모두 도보 경로 근처인 표본만 학습합니다.
- 안내 종료 후 유효 표본이 있으면 기존 속도와 세션 중앙값을 누적 표본 수로 가중해 `walkingSpeedMps`, `baseSpeedMps`, `maxSpeedMps`, `walkingSpeedSampleCount`를 갱신합니다.
- 원본 좌표는 진행 중인 메모리 안내 세션에서만 직전 표본으로 사용하고 경로 이탈·대중교통 구간·재탐색·안내 완료 시 제거합니다.

## 4. 사용자 흐름

```text
회원가입/로그인
  → 최초 이동 프로필
  → 메인 지도와 목적지 검색
  → 장소 상세 및 출발/도착 지정
  → 경로 탭(대중교통/택시/도보)
  → 경로 상세 바텀시트
  → 안내 시작
  → 정상 안내 또는 재탐색 제안
  → 놓침/이탈 확인
  → 현재 위치 기준 새 경로
  → 안내 종료 및 속도학습
```

## 5. 기능 요구사항

### F-AUTH — 계정

| ID | 기능 | 요구사항 | 완료 조건 |
|---|---|---|---|
| F-AUTH-01 | 회원가입 | 이메일과 8자 이상 비밀번호로 가입합니다. | 성공 시 JWT와 `profileCompleted=false`를 받고 프로필 화면으로 이동합니다. |
| F-AUTH-02 | 로그인 | 등록된 이메일과 비밀번호로 로그인합니다. | 성공 시 JWT와 사용자 정보를 받고 프로필 완료 여부에 따라 다음 화면을 결정합니다. |
| F-AUTH-03 | 로그아웃 | 클라이언트의 JWT와 사용자 상태를 삭제합니다. | 보호된 화면을 다시 열면 로그인 화면으로 이동합니다. |
| F-AUTH-04 | 회원 탈퇴 | 사용자의 계정·프로필·속도 집계를 삭제합니다. | 성공 시 `204 No Content`, 로컬 인증 상태도 삭제됩니다. |

중복 이메일은 `409 EMAIL_ALREADY_EXISTS`, 잘못된 로그인은 `401 INVALID_CREDENTIALS`로 처리합니다.

### F-PROFILE — 이동 프로필

| ID | 기능 | 요구사항 | 완료 조건 |
|---|---|---|---|
| F-PROFILE-01 | 최초 등록 | 유형, 보조기구와 네 가지 접근성 선호를 입력합니다. | 하나 이상의 사용자 유형과 모든 boolean 선호가 저장되면 `profileCompleted=true`입니다. |
| F-PROFILE-02 | 조회·수정 | 설정 화면에서 현재 프로필을 조회하고 전체 값을 수정합니다. | 저장 후 경로 검색은 수정된 프로필 스냅샷을 사용합니다. |
| F-PROFILE-03 | 속도학습 | 유효한 도보 위치 표본을 집계합니다. | 안내 종료 후 원본 좌표 없이 평균속도와 표본 수만 갱신됩니다. |

### F-MAP / F-PLACE — 지도와 장소

| ID | 기능 | 요구사항 | 완료 조건 |
|---|---|---|---|
| F-MAP-01 | 메인 지도 | 카카오맵을 표시하고 허용 시 현재 위치를 중심으로 이동합니다. | 지도 로드 실패·권한 거부 시 검색 기능은 계속 사용할 수 있습니다. |
| F-MAP-02 | 현재 위치 | 브라우저 위치 권한을 요청합니다. | 거부 시 권한 안내와 직접 검색 버튼을 표시합니다. |
| F-PLACE-01 | 장소 검색 | 2자 이상 검색어로 장소를 검색합니다. | 이름, 주소, 카테고리, 좌표, 전화번호, 장소 URL을 반환합니다. |
| F-PLACE-02 | 출발·도착 지정 | 검색 결과를 출발지 또는 목적지로 선택합니다. | 두 지점이 정해지면 경로 탐색 버튼이 활성화됩니다. |

### F-ROUTE — 경로 탐색

| ID | 기능 | 요구사항 | 완료 조건 |
|---|---|---|---|
| F-ROUTE-01 | 탭별 검색 | `TRANSIT`, `TAXI`, `WALK` 중 한 모드를 요청합니다. | 대중교통을 먼저 호출하고 다른 탭은 최초 진입 시 지연 호출합니다. |
| F-ROUTE-02 | 개인화 | 일반 경로에 프로필과 접근성 데이터를 적용합니다. | 일반/개인화 시간, 거리, 비용, 접근성 상태와 경고를 반환합니다. |
| F-ROUTE-03 | 정렬 | 경로를 이용 가능성 우선으로 정렬합니다. | `ACCESSIBLE → CAUTION → UNAVAILABLE`, 동일 상태에서는 개인화 시간이 빠른 순입니다. |
| F-ROUTE-04 | 경로 카드 | 요약정보를 리스트로 표시합니다. | 일반 ETA, 내 ETA, 환승, 보행거리, 요금과 핵심 경고가 보입니다. |
| F-ROUTE-05 | 상세 경로 | 선택 경로를 지도와 바텀시트로 표시합니다. | 모든 leg의 선, 출발·도착, 안내, 시설·저상버스 상태가 표시됩니다. |
| F-ROUTE-06 | 대체수단 | 접근 가능한 대중교통이 없으면 택시를 제안합니다. | `status=NO_ACCESSIBLE_ROUTE`, 빈 경로와 `fallbackModes=[TAXI]`를 처리합니다. |

택시는 자동차 경로·예상시간·예상요금까지만 제공합니다. 저상버스나 시설 상태가 확인되지 않으면 `UNKNOWN`으로 표시하며 안전을 보장하는 문구를 사용하지 않습니다.

### F-NAV — 실제 안내와 재탐색

| ID | 기능 | 요구사항 | 완료 조건 |
|---|---|---|---|
| F-NAV-01 | 안내 시작 | 유효한 `routeId`로 안내 세션을 만듭니다. | `routeRevision=1`, `status=ACTIVE`와 현재 경로를 반환합니다. |
| F-NAV-02 | 위치 처리 | 화면이 열린 동안 최대 5초에 한 번 좌표·기록시각·정확도를 보냅니다. | 현재 안내와 이탈 가능성을 반환하고 원본 위치를 DB에 저장하지 않습니다. |
| F-NAV-03 | 자동 제안 | 위치·시간으로 놓침 또는 이탈 가능성을 감지합니다. | 사용자의 확인 없이는 경로를 변경하지 않고 `REROUTE_SUGGESTED`를 표시합니다. |
| F-NAV-04 | 놓침 재탐색 | `MISSED_TRANSIT` 이벤트를 현재 위치와 함께 전송합니다. | 같은 세션의 `routeRevision`이 증가하고 새 출발점·경로·ETA를 반환합니다. |
| F-NAV-05 | 현재 역 보정 | 지하 GPS가 불안정하면 현재 역을 선택합니다. | `currentStation`이 있으면 GPS보다 역 좌표를 우선 사용합니다. |
| F-NAV-06 | 안내 종료 | 도착 또는 사용자 종료로 세션을 완료합니다. | 집계된 유효 속도 표본을 프로필에 반영하고 `COMPLETED`가 됩니다. |

## 6. 화면 상태와 문구 원칙

| 상태 | UI 처리 |
|---|---|
| 로딩 | 지도는 유지하고 경로 영역에 skeleton과 취소 가능한 로딩을 표시합니다. |
| 장소 결과 없음 | `검색 결과가 없습니다. 다른 장소명이나 주소를 입력해 주세요.` |
| 접근 가능한 경로 없음 | 오류 화면 대신 이유와 택시 탭 이동 버튼을 표시합니다. |
| 위치 권한 거부 | 현재 위치 없이 출발지를 직접 검색할 수 있게 합니다. |
| 외부 API 장애 | `현재 경로 정보를 불러오지 못했습니다.`와 재시도 버튼을 표시합니다. |
| 호출 한도 초과 | 같은 세션의 유효한 결과가 있으면 만료 전까지 표시하고, 없으면 재시도 안내를 표시합니다. |
| 오프라인 | 마지막 화면은 유지하되 새 검색·재탐색을 막고 연결 복구를 안내합니다. |
| 경로 만료 | 기존 경로로 안내를 시작하지 않고 새 검색을 요청합니다. |
| 정보 미확인 | `확인되지 않음` 배지와 사용자가 확인해야 할 항목을 표시합니다. |

## 7. 접근성 UI 요구사항

- 모바일 우선 레이아웃과 최소 44×44px 터치 영역을 사용합니다.
- 핵심 상태를 색상만으로 구분하지 않고 아이콘·텍스트를 함께 사용합니다.
- 지도 위 정보는 동일 내용을 바텀시트의 텍스트 목록으로도 제공합니다.
- 개인화 ETA와 위험 경고는 스크린리더가 읽을 수 있는 순서로 배치합니다.
- 움직이는 지도나 바텀시트 애니메이션은 `prefers-reduced-motion`을 존중합니다.

## 8. 개인정보 원칙

- 계정에 저장하는 위치 관련 값은 평균 보행속도, 속도 출처, 표본 수, 마지막 갱신시각뿐입니다.
- 위치 좌표는 안내 세션의 현재 상태 계산에만 사용하고 세션 종료 또는 취소 시 폐기합니다.
- 제3자 API에는 경로 탐색에 필요한 좌표만 전송하며 계정 ID·이메일·프로필 유형을 전송하지 않습니다.
- 탈퇴 시 계정, 프로필과 집계 속도를 삭제합니다.
- 실제 운영 전 개인정보 처리방침과 위치정보 이용 동의를 별도 법률 검토합니다.
