# 출발지 미지정 시 현재 위치 자동 사용 설계

## 목표

사용자가 출발지를 따로 지정하지 않고 목적지만 선택해도 현재 위치를 출발지로 설정하고 즉시 경로를 조회한다.

## 검토한 방식

1. **목적지 선택 시 현재 위치 확인(채택)**: 필요한 순간에만 위치 권한을 요청하므로 흐름이 짧고 기존 수동 출발지 기능도 유지된다.
2. 앱 진입 직후 위치 권한 요청: 경로를 찾기 전부터 권한 팝업이 떠서 거부율이 높을 수 있다.
3. 기본 지도 중심 좌표를 출발지로 사용: 실제 사용자 위치가 아닌 서울역 좌표로 잘못 안내할 위험이 있어 사용하지 않는다.

## 사용자 흐름

1. 출발지가 이미 있으면 기존처럼 목적지를 설정하고 바로 경로를 조회한다.
2. 출발지가 없으면 목적지 선택 직후 브라우저 현재 위치를 요청한다.
3. 위치 확인에 성공하면 `나의 현위치 (GPS)` 장소를 만들고 출발지와 목적지를 함께 저장한다.
4. 저장한 두 좌표로 현재 선택된 모드의 경로를 즉시 조회한다.
5. 위치 권한이 거부되거나 위치 확인에 실패하면 목적지는 유지하고 장소 검색 화면으로 이동한다.
6. 실패 안내에는 출발지를 직접 검색해 지정해야 한다는 문구를 표시한다.

## 상태와 오류 처리

- 위치 확인 중에는 중복 클릭과 중복 경로 요청을 막는다.
- 성공 시 `geolocationStatus`는 `GRANTED`, 지도 중심은 수신 좌표로 변경한다.
- 실패 시 `geolocationStatus`는 `DENIED`로 변경하고 경로 API는 호출하지 않는다.
- 브라우저가 위치 API를 지원하지 않는 경우도 권한 거부와 동일하게 처리한다.
- 초기 지도 중심용 서울역 좌표는 지도 표시용으로만 사용하며 출발지로 승격하지 않는다.

## 코드 경계

- 현재 위치를 `Place`로 변환하는 작은 헬퍼를 추가한다.
- 목적지 지정 핸들러는 출발지 존재 여부를 판단하고 현재 위치 확인 또는 기존 경로 조회를 선택한다.
- 실제 경로 요청은 기존 `handleQueryRoutes`를 그대로 사용해 API 계약을 변경하지 않는다.

## 검증

- 출발지가 없을 때 목적지를 지정하면 위치 확인 성공 후 현재 위치를 출발지로 사용해 경로 API를 호출한다.
- 출발지가 있으면 위치 API를 호출하지 않고 기존 출발지를 사용한다.
- 위치 권한이 거부되면 경로 API를 호출하지 않고 출발지 검색 화면과 안내 문구를 표시한다.
- 백엔드 API, 프론트 타입과 화면 디자인은 변경하지 않는다.
